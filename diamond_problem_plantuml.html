Diamond Problem & Orphan Rule Explained

1. C++ - The True Diamond Problem

C++ allows multiple class inheritance, leading to the full diamond: data duplication and method ambiguity.

2. Java - Half Diamond (Default Methods)

Java prevents multiple class inheritance, but default methods on interfaces can still cause method ambiguity.

3. Rust - No Duplicate Impl (Within a Crate)

Rust does not allow implementing the same trait for the same type twice, even in your own crate.

4. Rust - No Duplicate Impl (Across Crates)

Without the orphan rule, two foreign crates could each implement a foreign trait for a foreign type.

5. Rust - The Diamond That Could Happen

If the orphan rule did not exist, an app depending on two crates would face ambiguity.

6. Rust - Orphan Rule Prevents It

The compiler rejects the conflicting impls at their source. The diamond can never form.

Summary

Language Strategy
C++ Allows diamond, gives manual tools (virtual inheritance, explicit disambiguation)
Java Prevents class diamond (single inheritance), catches interface conflicts at compile time
Rust Eliminates the problem structurally (no inheritance, orphan rule, single impl per trait+type)
